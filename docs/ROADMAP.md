### 誠實策展原則的實踐案例(供後續輪次遵循)

- **查無文獻不畫邊**:新莊地藏庵厲祀起家,二輪查證確認無唐山分香記載——維持僅收廟宇節點;東港東隆宮源流為先民攜香火、無祖廟記載——同樣只收節點不畫邊。
- **未立案不收**:協天廟戰後四壇堂(志心堂、德顯堂、明聖堂、聖天堂)查無立案與可定位資訊——寧缺勿濫,記入待辦俟有出處再收。
- **政府出處逐字確認**:茄萣萬福宮「源自南鯤鯓代天府」以茄萣區公所官網原文逐字核對後才標「確定」;麥寮聚寶宮王船傳說以鄉公所頁全文佐證後才收邊。
- **無可驗證出處不收**:范府千歲獨立系統查無可考文獻鏈、鹿港富美宮無可驗證網頁(wiki 404)、新竹富美宮三府組成歧異——三者皆誠實排除並記入待辦(v4.2)。
- **同名異系要分辨**:鹿港護安宮吳府(五部鬚、專精醫科)與南鯤鯓三王吳孝寬為不同源流——單府王爺最易混淆處,已在註冊表註記載明。
- **爭議並陳**:行天宮源流二說(覺修宮系 vs 協天廟系)以兩條邊並存標「存爭議」;祀典武廟荊州說/東山說於註記並陳。
- **更正要留痕**:台中蓮社創建年更正為 1950(非 1951);湛然寺「先天派」為誤傳(實為天台法脈);鹿港「四川天竺尊巖」說時序與張志相 2015 考證不合——皆於資料註記與決策日誌留紀錄。
- **出處親驗**:所有 evidenceUrl 寫入前逐一複驗(HTTP 200+內容相符);老網站注意 Big5/UTF-16LE 編碼。
- **外部節點原則**:中國祖廟/已消失古廟/未收錄廟宇以外部節點呈現(座標近似值);不可定位的源頭(如先天派萬全堂)寧可不畫線。

## 二、擴充評估候選(依提案人 2026-08-31 列舉方向整理)

> 每項評估構面:資料模型影響 / 資料來源 / 挑戰與敏感議題 / 建議優先序。
> 優先序僅為策展成本與模式成熟度之綜合判斷,立項時可重議。

### E1. 儒釋道神明系統及廟宇擴充

- **內容**:道教系統——玄天上帝(MOI 未比對名 100+ 筆)、清水祖師(134)、三官大帝(121)、神農大帝(108)、瑤池金母(102)、中壇元帥(144)、廣澤尊王(86)、雷祖/斗母等;儒教——孔廟(官祀體系)、文昌帝君、魁星;釋教——三寶佛(76)、藥師佛、彌勒等;王爺擴充——三山國王(185)、開漳聖王(79)、池府/吳府等單府王爺。
- **資料模型影響**:低——deities.js 註冊表依 D9 既有模式擴充,源流邊按系統逐批策展,管線已驗證(文武大眾爺輪即此模式)。
- **資料來源**:MOI 底層已收錄;沿革策展沿用現行流程(廟方官網+文資網+學術文獻)。
- **挑戰**:王爺系統分香網絡龐雜(南鯤鯓系統文獻豐,適合首發);孔廟屬官祀體系,「源流邊」語意需另議(承建/改制?)。
- **▶ 執行狀態**:王爺首批(v3.0)——富美宮王船→麻豆、王船→南鯤鯓、南鯤鯓→茄萣萬福宮(1795 確定)、南鯤鯓→哈瑪星代天宮(1949),溫府千歲納入註冊表,東港東隆宮收節點;深挖(v4.0)——碧湖宮(1786 最早分靈,官網載)、「大湖香宿蕭壢」謁祖、麻豆迎香祭;單府王爺(v4.1/v4.2)——池府(碧湖宮/海埔)、蕭府(北斗富美舘+聚寶宮/梧棲/花壇富美系)、朱府(水裡港福順宮)、吳府(鹿港護安宮,獨立系);范府查無可考鏈不收。後續:鹿港/新竹富美宮俟出處、南鯤鯓網絡持續擴充。
- **優先序**:高(模式成熟,建議順序:王爺擴充→玄天上帝→清水祖師)。

### E2. 原鄉語言宗教系統(泉州/漳州/潮州)

- **內容**:以移民原鄉為網絡維度——泉州系(保生大帝、安海龍山寺觀音、同安香火)、漳州系(開漳聖王、東山關帝)、潮州系(三山國王,多為潮州客家移民)。既有源流資料已隱含此維度(安海/同安=泉州,東山=漳州)。
- **資料模型影響**:中——屬**新網絡維度**(非主祀神)。可行方案:(a) temples 加 `originGroup` 屬性;(b) 以 lineage 邊 deity 欄位作族群標籤(同齋教 D11 模式);需立新決策定案。
- **資料來源**:移民史與方志文獻豐富(寺廟台帳、各地志書);但多數廟宇的原鄉屬性**無法從登記資料判讀**,需逐廟考證。
- **挑戰**:原鄉≠語言≠人群,易過度簡化;同一神明多原鄉並存(如媽祖湄洲屬泉州府但分香遍各屬);清代行政區劃變動。
- **優先序**:中(概念與本圖核心「源流」高度契合,但考證成本大;可先以現有泉/漳節點做小規模試作)。

### E3. 藏傳佛教與密宗(金剛乘)

- **內容**:各教派(寧瑪、薩迦、噶舉、格魯、覺囊等)在台佛法中心、閉關中心、佛學會;兩波傳入——1950s 隨漢地學密居士來台、1980s 藏傳上師親自來台弘法。
- **資料模型影響**:低——D10「法脈」模型直接適用(上師→中心傳承鏈);外部節點=印度/尼泊爾/圖伯特各派祖庭(可定位)。
- **資料來源**:立案中心已在 MOI 底層(可 grep 藏傳/喇嘛/佛學會相關名);未立案中心多,需逐中心考證。
- **挑戰**:傳承真偽爭議(未經認證的上師)——收錄標準需先定義(是否僅收有明確傳承譜系者?);部分議題具政治敏感度。
- **優先序**:中低(建議先以格魯派(日常法師/福智?)或噶舉派某中心做模式試作,或整體暫緩)。

### E4. 日治時期神道與日本佛教(含真言密教)遺留

- **內容**:神社遺構——桃園神社(忠烈祠)、通霄神社、嘉義神社、高雄神社(壽山)、花蓮港神社等;日本佛寺——臨濟護國禪寺(圓山)、西本願寺(萬華)、淨土宗善導寺(已收,1895 前身有日治脈絡)、慶修院(吉野布教所,真言宗)、曹洞宗/淨土真宗布教所遺跡。
- **資料模型影響**:中——多數為**遺構/古蹟而非活躍宗教場所**,現有 landingType 無此語意;需新增類型(如「歷史遺構」)或獨立圖層(可能影響 UI 三層結構)。
- **資料來源**:文化資產網對神社遺構紀錄完整(多為古蹟);日治宗教史研究成熟(政府檔案、寺廟台帳)。
- **挑戰**:與「進香地圖」的範疇匹配度——遺構無進香活動,但作為「信仰地景的歷史層」與本圖概念相容;戰後改制(忠烈祠化)的身分敘事需謹慎。
- **優先序**:中(資料基礎好;建議以「桃園神社+慶修院+臨濟護國禪寺」三點試作歷史遺構層)。

### E5. 原住民祖靈信仰與聖地遺跡 ⚠️ 高敏感

- **內容**:各族聖地(邵族 Lalu 聖島、魯凱/布農大鬼湖小鬼湖聖湖、撒奇萊雅祖靈地)、祖靈屋(排灣)、泰雅聖石與神木群;以及**西拉雅阿立祖/祀壺信仰**(頭社夜祭等,漢原合流、公開祭典)。
- **資料模型影響**:高——節點性質與廟宇差異大(聖地無「主祀神/沿革/香客大樓」欄位語意);需全新資料模型或僅收「可公開祭典場所」。
- **⚠️ 敏感議題(本項成敗關鍵)**:
  1. 聖地位置公開可能導致侵擾、商業化、盜採——部分聖地位置為部落刻意保密;
  2. 原住民族傳統智慧創作保護(原創法)對文化表達的權利規範;
  3. **任何收錄必須先與該族群/部落組織諮詢並取得同意**;未獲同意者不收;
  4. 部分地點應只記「存在但不公開座標」,或以行政區層級模糊化呈現。
- **資料來源**:人類學文獻(中研院民族所、原民會);西拉雅祀壺信仰因祭典公開且學界研究多,是唯一可先行子項。
- **優先序**:西拉雅祀壺——中(可與 E1 併輪);各族聖地——**暫緩,待社群諮詢**,無共識前不立項。

### E6. 其他民俗民間宗教處所

- **內容**:陰廟系統(有應公、萬善爺、姑娘廟、大眾爺擴充);自然崇拜(樹王公、石頭公、榕樹公);鸞堂/扶鸞系統(協天廟戰後六壇堂已在待辦);一貫道(明明上帝 151 筆);軒轅教、天帝教、天德教等新興宗教;齋堂擴充(台中慎齋堂、嘉義及各地)。
- **資料模型影響**:低至中——多數可沿用現有模型;「進香地圖」的**範疇邊界**需先定義(哪些宗教/場所屬於本圖?基督教/天主教/伊斯蘭是否納入?)。
- **資料來源**:MOI 底層已收立案者;陰廟多未立案,需田野層級策展。
- **挑戰**:陰廟的「參拜」語感與一般廟宇不同(民俗禁忌個別差異大);新興宗教的教派爭議。
- **▶ 執行狀態**:鸞堂部分已於 v3.0(2026-08-31)完成——九份明聖宮、新店明聖宮(青潭)分靈自礁溪協天廟(待查);志心堂、德顯堂、明聖堂、聖天堂四堂未立案、無可定位資訊,誠實不收。其餘子項(陰廟、自然崇拜、一貫道等)未動。
- **優先序**:鸞堂——已完成可收錄部分;範疇邊界決策——先做(見下);其餘中低。

### O 系列候選:開發與優化項目(技術面,2026-09-01 彙整)

> 與 E 系列(內容擴充)互補的工程面向候選;皆未承諾排程,立項時於 REQUIREMENTS 記錄。

- **O1. CI 自動驗證**:以 GitHub Actions 在 push/PR 時自動執行 `node tools/validate-data.js`(含 U+FFFD 檢查),把「驗證必跑」從紀律升級為管線強制;可再加 moi 重產後的 diff 檢查。價值高、規模小。
- **O2. 源流圖層圖例與關係篩選**:圖層目前有六種關係線样式(分香/謁祖/割火/遶境/承繼/法脈/輪祀)與三級透明度(確定/存爭議/待查),但無圖例說明;且源流線不隨神明篩選同步。加圖例(L.control)與「依網絡篩選源流線」能大幅提升可讀性。
- **O3. evidenceUrl 連結健檢工具**:65 個出處連結會因網站改版而失效(本專案已遇 kaitaimazutemple.com 域名易主、TNL 403 等案例);寫一支 `tools/check-evidence.js` 定期回報 HTTP 狀態與關鍵字漂移,維持「出處可查證」承諾。
- **O4. 行動裝置實測與 UX 調校**:打卡→足跡→匯出流程僅做過桌面 headless E2E;實機(iOS Safari/Android Chrome)的 localStorage、檔案下載與地圖手勢值得實測一輪,並據此調校 responsive.css。
- **O5. 個人足跡跨裝置**:D4 當時決策「暫不做後端」;若未來有跨裝置同步需求,可評估輕量方案(如 GitHub Gist OAuth、或極簡自架 API),屆時需回 REQUIREMENTS 重議 D4。
- **O6. 資料更新週期**:內政部 8203 資料會更新;可每季重跑 `import-moi-data.js` 並 diff(注意註冊表擴充後的分類變化),於 DATA_SOURCES.md 記錄版本。
- **O7. 分享與 Meta**:加 Open Graph 標籤與代表圖,讓地圖連結在通訊軟體分享時有預覽;規模極小。
- 技術債清理(可隨手做):`.lang-toggle` 失效 CSS、`deities.js` 註冊表數量註記與實數同步。

## 三、評估流程

```
候選項(E1–E6)
  → repo 討論/提案
  → REQUIREMENTS.md 立決策編號(D12+)定案
  → 資料模型影響評估(必要時先做 schema 試作)
  → 小規模試作一批(3–5 節點/邊)
  → node tools/validate-data.js 驗證
  → 分支 → 核准 → 合併 → 自動部署
```
